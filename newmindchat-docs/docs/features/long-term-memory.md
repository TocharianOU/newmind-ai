# 长期记忆功能

NewmindChat 支持跨会话的长期记忆功能，能够自动记住和检索历史对话中的关键信息。

## 功能概述

长期记忆系统可以帮助 AI 助手：

- 记住用户提到的人名、项目名、概念
- 保存基础设施信息（如服务器配置、数据库连接等）
- 记录索引和数据分布信息
- 跨会话智能检索相关历史上下文

## 工作原理

### 1. 自动实体提取

在每次对话结束后，系统会自动分析对话内容，提取以下类型的实体：

- **人物 (Person)**: 对话中提到的人名、团队成员等
- **项目 (Project)**: 项目名称、代号、任务等
- **概念 (Concept)**: 技术概念、业务术语、专业名词
- **基础设施 (Infrastructure)**: 服务器、数据库、API 端点等技术资源
- **索引 (Index)**: Elasticsearch 索引、数据表、数据源等
- **其他 (Other)**: 其他重要信息

### 2. 智能记忆检索

当您发起新对话时，系统会智能判断是否需要检索历史记忆：

- 检测关键词，如"之前"、"上次"、"记得"、"earlier"、"previous"等
- 识别对已知实体的引用
- 根据上下文判断是否涉及历史信息

如果需要检索，系统会自动：

1. 从长期记忆中搜索相关实体
2. 将相关记忆注入到对话上下文
3. 帮助 AI 基于历史信息给出更准确的回答

### 3. 记忆管理

您可以通过记忆面板管理所有保存的记忆：

- **查看记忆**: 按类型查看所有保存的实体
- **搜索记忆**: 使用关键词快速查找相关记忆
- **删除记忆**: 删除不需要的或过时的记忆
- **清空记忆**: 一键清除所有长期记忆

## 使用方法

### 打开记忆面板

在聊天界面的顶部工具栏中，点击 **"记忆"** 按钮即可打开记忆侧边栏。

### 查看记忆

1. 在记忆面板中，可以看到按类型分类的所有实体
2. 点击类型标签可以筛选特定类型的记忆
3. 点击具体的记忆项可以查看详细信息

### 搜索记忆

1. 在记忆面板的搜索框中输入关键词
2. 按回车或点击"搜索"按钮
3. 系统会返回匹配的记忆列表

### 删除记忆

1. 点击要删除的记忆项
2. 在详情面板中点击"删除"按钮
3. 确认删除操作

### 清空所有记忆

1. 在记忆面板底部点击"清空所有记忆"按钮
2. 在确认对话框中确认操作
3. 所有记忆将被永久删除

## 使用示例

### 示例 1：记住项目信息

**第一次对话：**

> 用户：我在开发一个叫 ProjectX 的电商平台项目，使用的是 Elasticsearch 集群，索引名是 products_v2。

系统会自动提取并保存：
- 项目名称：ProjectX
- 基础设施：Elasticsearch 集群
- 索引：products_v2

**后续对话：**

> 用户：上次那个电商平台项目的索引配置是什么？

系统会自动检索到 ProjectX 相关的记忆，并基于历史信息回答。

### 示例 2：记住人员信息

**第一次对话：**

> 用户：我的同事 Alice 负责前端开发，Bob 负责后端 API 设计。

系统会自动保存：
- 人物：Alice (前端开发)
- 人物：Bob (后端 API 设计)

**后续对话：**

> 用户：Alice 负责的部分是什么？

系统会检索到 Alice 的记忆，回答"前端开发"。

### 示例 3：技术概念记忆

**第一次对话：**

> 用户：我们使用 CQRS 模式来分离读写操作，读取端使用 Elasticsearch，写入端使用 PostgreSQL。

系统会保存：
- 概念：CQRS 模式
- 基础设施：Elasticsearch (读取端)
- 基础设施：PostgreSQL (写入端)

**后续对话：**

> 用户：之前提到的 CQRS 架构中，读取端用的什么？

系统会基于记忆回答"Elasticsearch"。

## 隐私与安全

- **本地存储**: 所有记忆数据默认存储在本地数据库中，不会上传到云端
- **用户控制**: 您可以随时查看、删除或清空所有记忆
- **自动清理**: 长期未使用的低相关度记忆可能会被自动清理（未来版本）

## 最佳实践

### 1. 清晰描述重要信息

在对话中清晰地描述重要的人名、项目、配置等信息，有助于系统更准确地提取实体。

**好的例子：**
> "我们的生产环境 Elasticsearch 集群地址是 prod-es.example.com，索引名称是 logs-2024"

**不好的例子：**
> "那个 ES 在那台服务器上"

### 2. 定期清理过时记忆

随着时间推移，一些项目、配置可能会发生变化。定期查看并删除过时的记忆，可以避免 AI 使用错误的历史信息。

### 3. 利用相关度评分

记忆面板会显示每个实体的相关度评分（0-100%）。相关度高的记忆更容易被检索和使用。

### 4. 合理使用引用关键词

在需要使用历史信息时，使用明确的引用关键词可以帮助系统更好地检索记忆：

- "之前提到的..."
- "上次讨论的..."
- "记得那个..."
- "earlier mentioned..."
- "the previous..."

## 技术细节

### 存储结构

每个实体记忆包含以下信息：

- **名称 (name)**: 实体的名称或标识
- **类型 (entity_type)**: 实体类型（person/project/concept/infrastructure/index/other）
- **内容 (content)**: 实体的描述或上下文
- **元数据 (metadata)**: 附加的结构化信息
- **相关度 (relevance)**: 相关度评分 (0-1)
- **来源会话 (source_chat_id)**: 实体来源的对话 ID
- **创建/更新时间**: 时间戳

### 检索算法

记忆检索使用以下策略：

1. **关键词匹配**: 检测历史引用关键词
2. **实体识别**: 识别对话中提到的已知实体
3. **语义相关性**: 基于对话内容的语义相关性（未来版本）

### 隐私保护

- 记忆数据使用用户 ID 隔离，不同用户的记忆互不影响
- 本地存储模式下，数据保存在应用本地数据库
- 支持一键清空所有记忆数据

## 常见问题

### Q: 记忆会占用多少存储空间？

A: 每个实体记忆通常只占用几百字节到几 KB 的空间。即使保存数千条记忆，总占用空间也很小（通常小于 10MB）。

### Q: 记忆会被自动清理吗？

A: 当前版本不会自动清理记忆。您需要手动删除不需要的记忆。未来版本可能会添加自动清理功能。

### Q: 记忆会影响响应速度吗？

A: 记忆检索是异步进行的，对响应速度的影响极小（通常 < 100ms）。实体提取在对话完成后异步执行，不会阻塞响应。

### Q: 可以导出记忆数据吗？

A: 当前版本暂不支持导出功能。未来版本将支持导出为 JSON 或 CSV 格式。

### Q: 记忆会同步到其他设备吗？

A: 当前版本记忆存储在本地，不会自动同步。未来版本可能会支持云端同步功能。
